/control/echo backgroundbackground · for non-physicists背景知识 · 写给非物理专业

A research question for a muography project fits in one sentence.一个缪子成像项目的研究问题，一句话就能说清。

Background · Example questions问题示例

Can a 1 m² telescope in the tunnel at chainage 2+300 detect a 3 m void within 20 m above the crown in one month? How precisely can three months of data measure the mean density of the overburden above a planned shaft? Does a 5 cm lead absorber improve the contrast enough to pay for its weight?

隧道里程 2+300 处的一台 1 m² 望远镜，能否在一个月内探测到拱顶以上 20 m 范围内一个 3 m 的空洞？三个月的数据能把拟建竖井上方覆盖层的平均密度测到多准？5 cm 厚的铅吸收体带来的对比度提升，值不值得它的重量？

Background · Significance of a feature特征的显著性

If the model without the void predicts N muons along a direction and the void adds ΔN, the feature stands out by about ΔN/√N standard deviations. Both N and ΔN grow with exposure time, so significance grows only as √time. That is the 1/√N rule of Week 1 again, now deciding how long the instrument stays underground.

若无空洞的模型在某个方向上预测 N 个缪子，空洞使其增加 ΔN，则这个特征的显著性约为 ΔN/√N 个标准差。N 和 ΔN 都随测量时间增长，所以显著性只按 √时间 增长。这又是第 1 周的 1/√N 规律，只是现在它决定仪器要在地下待多久。

For muography projects用于缪子成像工程

Use the feasibility planner on this page with your site's numbers. A good muography proposal states the target (void size, density contrast), the overburden and its uncertainty, the detector area and acceptance, the exposure time, and the significance it expects, before any data are taken.

用本页的可行性规划器代入你场地的数字。一份好的缪子成像提案应当在采集任何数据之前写明：目标（空洞尺寸、密度对比）、覆盖层厚度及其不确定度、探测器面积和接受度、测量时间，以及预期的显著性。

New to muons, units such as g/cm² or m.w.e., or muography? Start with the background primer.还不熟悉缪子、g/cm² 或米水当量这类单位，或缪子成像？先读入门背景。

TOY MODEL · approximations近似

        
Statistical precision: σ/ε = √((1 − ε)/(εN)) for an efficiency, r/√(εN) for a mean. The total is √(stat² + sys²), so it never falls below the systematic. Cost: constant CPU per generated event, with a default of 0.34 ms from our Week 10 run (200 000 muons, about 68 CPU-seconds on two threads). It assumes perfect scaling over cores and no queue, failed jobs or analysis time. "Feasible" means production fits in half the days left. Measure your own ms per event with a pilot run; it changes by orders of magnitude with geometry, energy and optical photons.

        
统计精度：效率为 σ/ε = √((1 − ε)/(εN))，均值为 r/√(εN)。总不确定度为 √(stat² + sys²)，所以永远不会低于系统误差。代价：每个产生事例的 CPU 时间恒定，默认 0.34 ms，取自我们第 10 周的运行（20 万个缪子，双线程约 68 CPU 秒）。假设多核完美扩展，不考虑排队、失败作业和分析时间。“可行”指生产只占剩余天数的一半。请用试跑测出你自己的每事例耗时；它会随几何、能量和光学光子相差几个数量级。

      

    

  


  

    
/control/saveHistory12.2 · the last gate is a defence12.2 · 最后一关是答辩

    

      
Treat your simulation as an instrument someone else could rebuild and challenge.把你的模拟当作一台别人能重建、能质疑的仪器。

      

        
Definition 12.2 · Defence weights答辩权重

        
A defence is graded on six parts: the problem 20%, the implementation 20%, validation 25%, analysis 15%, communication 10%, and code and reproducibility 10%. Validation carries the most weight on its own.

        
答辩按六个部分评分：问题 20%，实现 20%，验证 25%，分析 15%，表达 10%，代码与可复现性 10%。单项中验证的权重最大。

      

      

        
Example 12.1 · A ten-minute defence十分钟答辩

        
1 min: the physics question, clear without slides. 3 min: simulation design and the key implementation choices. 3 min: validation, with uncertainties and the reference. 1 min: known limitations. The rest: questions, at least one of them a referee's question.

        
1 分钟：物理问题，不看幻灯片也能听懂。3 分钟：模拟设计和关键实现选择。3 分钟：验证，含不确定度和参照。1 分钟：已知局限。其余时间：提问，其中至少一个是审稿人式的问题。

      

      

        
Required boundary statement必需的边界声明

        
Name at least one physically important effect your virtual experiment ignores, and its consequence. If you used musrSim, also name one application-specific behaviour (a magic volume name, a fork-dependent command, a parameterised response, the physics list) and how you verified it against the installed source. Course-W10-a is a model answer.

        
至少说出一个被你的虚拟实验忽略的重要物理效应及其后果。如果用了 musrSim，还要说出一个应用特有的行为（特殊体积名、依赖分支的命令、参数化响应、物理列表），以及你如何对照已安装的源码核实它。Course-W10-a 就是一个范例答案。

      

      
The 10% for code and reproducibility is checked by doing it: an evaluator clones the repository, rebuilds from scratch, runs the macro and gets the headline number without asking you anything. Record the executable version, the Geant4/ROOT environment, macros, seed strategy, thread count and the analysis script.

      
代码与可复现性这 10% 是靠实际操作来检查的：评审克隆仓库、从零编译、运行宏，不问你任何问题就得到核心数字。要记录可执行程序版本、Geant4/ROOT 环境、宏文件、种子策略、线程数和分析脚本。

    #!/bin/bash
# repro_check.sh -- what an evaluator does before your defence: clone, rebuild from scratch,
# run your macro, and compare your headline number with the one in your slides.
# Usage: bash repro_check.sh <git-url> <tag> <app-dir> <macro> "<analysis command>" <expected> <tolerance>
# Example (Week 10 as a defence package):
#   bash repro_check.sh https://github.com/you/tf-musr.git v1.0 week10 tf.mac \
#        "python3 asymmetry.py data/tf_10mT.root" 1.3573 0.0040
set -euo pipefail
URL=$1; TAG=$2; APP=$3; MACRO=$4; ANALYSIS=$5; EXPECTED=$6; TOL=$7
WORK=$(mktemp -d)
echo "== environment"
geant4-config --version
root-config --version 2>/dev/null || echo "ROOT: not installed (uproot analysis only)"
python3 -c "import uproot, awkward, scipy; print('uproot', uproot.__version__, '| awkward', awkward.__version__, '| scipy', scipy.__version__)"

echo "== clean checkout of $TAG"
git clone -q --branch "$TAG" --depth 1 "$URL" "$WORK/src"
git -C "$WORK/src" log -1 --format='commit %H  %ad'
test -z "$(git -C "$WORK/src" status --porcelain)" || { echo "FAIL: tree not clean"; exit 1; }

echo "== build from scratch"
cmake -S "$WORK/src/$APP" -B "$WORK/build" -DCMAKE_BUILD_TYPE=Release > "$WORK/cmake.log"
cmake --build "$WORK/build" -j4 > "$WORK/build.log"

echo "== run"
cd "$WORK/build" && mkdir -p data
EXE=$(find . -maxdepth 1 -type f -perm -u+x ! -name '*.sh' | head -1)
"$EXE" "$MACRO" > run.log 2>&1
grep -E "seed|Run complete|Field at" run.log || true

echo "== analysis"
OUT=$($ANALYSIS)
echo "$OUT"
GOT=$(echo "$OUT" | grep -E "^f +=" | awk '{print $3}')
python3 - "$GOT" "$EXPECTED" "$TOL" <<'EOF'
import sys
got, exp, tol = map(float, sys.argv[1:])
ok = abs(got - exp) <= tol
print(f"headline: got {got}, slides say {exp}, tolerance {tol} -> {'REPRODUCED' if ok else 'NOT REPRODUCED'}")
sys.exit(0 if ok else 1)
EOF
