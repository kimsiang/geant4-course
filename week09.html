An application layer: running Geant4 from a text file.应用层：用一个文本文件驱动 Geant4。

Background · What musrSim ismusrSim 是什么

musrSim is a Geant4 application written for μSR, a materials-science technique that implants muons from an accelerator into a sample. Its geometry, beam and output are set in a text macro instead of C++. The idea transfers: many groups build such an application once and then run many configurations from macros.

musrSim 是为 μSR 编写的 Geant4 应用程序。μSR 是一种材料科学技术，把加速器产生的缪子注入样品。它的几何、束流和输出都在文本宏中设置，而不是写在 C++ 里。这种思路是通用的：许多课题组把应用程序写一次，然后用宏运行各种配置。

Background · Jagged arrays锯齿数组

One muon may fire one detector plane, or five. A table column such as "detector IDs hit" then holds a list of different length in each row: a jagged array. Select the plane you want before flattening the lists, or rows from different events get mixed up.

一个缪子可能只触发一个探测平面，也可能触发五个。于是像“被击中的探测器编号”这样的列，每一行是一个长度不同的列表：锯齿数组。先选出你要的平面，再把列表展平，否则不同事例的行会被混在一起。

For muography projects用于缪子成像工程

If you are on the muography track, skim this week for the macro-driven workflow and the jagged-array analysis. Both appear in every multi-plane telescope analysis. The μSR beam details can be skipped.

如果你走缪子成像方向，本周略读即可，重点看由宏驱动的工作流程和锯齿数组分析，这两者在每一个多层望远镜的分析中都会出现。μSR 束流的细节可以跳过。

New to muons, units such as g/cm² or m.w.e., or muography? Start with the background primer.还不熟悉缪子、g/cm² 或米水当量这类单位，或缪子成像？先读入门背景。

musrSim does not replace Geant4. It packages it.musrSim 不是取代 Geant4，而是把它打包起来。

Definition 9.1 · Three layers of a musrSim run一次 musrSim 运行的三层

your macro → musrSim executable → Geant4 + ROOT. The macro states the experiment; musrSim interprets the commands and builds the application; Geant4 transports the particles and ROOT stores the selected observables. Commands beginning with /run, /vis, /control are Geant4's; /musr/… and much of /gun/… belong to this distribution.

你的宏 → musrSim 可执行文件 → Geant4 + ROOT。宏描述实验；musrSim 解释命令并构建应用；Geant4 输运粒子，ROOT 保存选定的可观测量。以 /run、/vis、/control 开头的命令属于 Geant4；/musr/… 以及大部分 /gun/… 属于这个发行版。

Geometry as a command grammar把几何写成命令语法

/musr/command construct <solid> <name> <dimensions> <material> <x y z> <mother> <rotation> <sensitivity> <volumeID>
# box  : half-x half-y half-z           (mm)
# tubs : rmin rmax half-z phi0 dphi     (mm, deg)
# mother: log_<name>, constructed EARLIER; World uses no_logical_volume
# sensitivity: musr/ScintSD (a detector) or dead; volumeID becomes det_ID

A first musrSim macro (first_sim.mac, a preset in the toy below) has four ingredients: a World (500 500 500 is a 1 m cube), a sensitive slab (50 50 5 is 100 × 100 × 10 mm, volume ID 1), a beam, and /run/beamOn. There is no /run/initialize: musrSim initialises in its C++ layer.

第一个 musrSim 宏（first_sim.mac，即下方玩具中的预设）有四个要素：World（500 500 500 是 1 m 的立方体）、一块灵敏板（50 50 5 即 100 × 100 × 10 mm，体积 ID 为 1）、束流，以及 /run/beamOn。宏里没有 /run/initialize：musrSim 在其 C++ 层完成初始化。

The beam is more than a particle gun束流不只是粒子枪

The /gun family exposes what matters for muon experiments: vertex and spread, momentum and smearing, tilt and pitch, spin polarization, decay-time limits and TURTLE input. For vertexsigma, a positive value gives a Gaussian spread, a negative value a uniform one, and zero none. A 29.8 MeV/c surface muon has 4.1 MeV kinetic energy and stops within about 1.5 mm of plastic. Its spin is the state that precesses in Week 10, which is why polarization sits in the beam model.

/gun 系列命令提供了缪子实验关心的一切：顶点及其展宽、动量及其弥散、倾角与 pitch、自旋极化、衰变时间窗以及 TURTLE 输入。对 vertexsigma，正值给出高斯展宽，负值给出均匀分布，零表示无展宽。29.8 MeV/c 的表面缪子动能为 4.1 MeV，在约 1.5 mm 的塑料内就会停止。它的自旋正是第 10 周中会进动的状态，所以极化写在束流模型里。

t1->Draw("det_edep","det_ID==11")9.2 · the t1 tree9.2 · t1 树

One event can contain many hits, and detector identity is data.一个事例可以有许多击中，探测器身份本身就是数据。

Definition 9.2 · Two layers of the t1 treet1 树的两层

Event-level branches hold one value per event: muIniPosX, muDecayTime, muDecayDetID. Hit branches hold det_n values per event: det_ID, det_edep, det_time_start, det_x. Do not flatten or select the two layers the same way.

事例级分支每个事例一个值：muIniPosX、muDecayTime、muDecayDetID。击中分支每个事例有 det_n 个值：det_ID、det_edep、det_time_start、det_x。这两层不能用同样的方式展平或选择。

Units, from the musrsim-sms source: energies in MeV, times (muDecayTime, det_time_start) in µs, positions in mm. Event-level branches start every event at the sentinel −1000, meaning "not defined for this event". Several counters can share the musr/ScintSD type; the integer volume ID tells them apart, so selecting a detector is an analysis operation, not a new C++ class.

由 musrsim-sms 源码可知单位：能量 MeV，时间（muDecayTime、det_time_start）µs，位置 mm。事例级分支在每个事例开始时被设为哨兵值 −1000，表示“该事例中未定义”。多个计数器可以共用 musr/ScintSD 类型，靠整数体积 ID 区分。因此选择某个探测器是一个分析操作，而不是新写一个 C++ 类。

A branch you do not analyse still costs I/O, storage and parsing time. Decide which quantities answer the question, run a small sample with extra diagnostics, then switch the rest off with /musr/command rootOutput <branch> off and the storeOnly… switches.

不分析的分支照样消耗 I/O、存储和解析时间。先确定哪些量能回答问题，用带额外诊断的小样本试跑，然后用 /musr/command rootOutput <branch> off 和 storeOnly… 系列开关关掉其余分支。

    make_synthetic_t1.pyANALYSIS
    """Write data/musrSim_201.root: a SYNTHETIC tree with the branch names, jagged hit
structure, units (MeV, microseconds) and -1000 sentinels of musrSim's t1 tree.
It is NOT musrSim output. It exists so the Week 9 analysis can be run and checked
before you have a musrSim build. Physics in it: mu+ lifetime 2.1969811 us (PDG).
"""
import os

import awkward as ak
import numpy as np
import uproot

rng = np.random.default_rng(2026)
N = 20000
TAU = 2.1969811
os.makedirs("data", exist_ok=True)

# Where the muon decayed: 80% in the sample (volume ID 201), 15% in the counter 11, 5% elsewhere/escaped
where = rng.choice([201, 11, -1000], size=N, p=[0.80, 0.15, 0.05])
t_dec = rng.exponential(TAU, N)
mu_decay_time = np.where(where == -1000, -1000.0, t_dec)          # sentinel when not defined
mu_decay_det = where.astype(np.int32)

det_ID, det_edep, det_t = [], [], []
for i in range(N):
    ids, ed, tt = [], [], []
    if where[i] != -1000 and rng.random() < 0.95:                  # the stopping muon deposits in its volume
        ids.append(int(where[i])); ed.append(float(rng.normal(4.1, 0.3))); tt.append(float(rng.normal(0.010, 0.002)))
    for counter in (1, 11):                                         # decay positron may hit a counter
        if where[i] != -1000 and rng.random() < 0.30:
            z = rng.normal()
            ids.append(counter); ed.append(float(max(0.05, 1.6 + 0.12 * -np.log(z * z + 1e-12)))); tt.append(float(t_dec[i] + rng.normal(0, 0.001)))
    det_ID.append(ids); det_edep.append(ed); det_t.append(tt)

det_ID = ak.Array(det_ID)
branches = {
    "muDecayDetID": mu_decay_det,
    "muDecayTime": mu_decay_time,
    "det": ak.zip({"ID": ak.values_astype(det_ID, np.int32), "edep": ak.Array(det_edep), "time_start": ak.Array(det_t)}),
}

    f.mktree("t1", {k: v.type if hasattr(v, "type") else v.dtype for k, v in branches.items()},
             counter_name=lambda counted: counted + "_n",
             field_name=lambda outer, inner: outer + "_" + inner)
    f["t1"].extend(branches)

    analyse_t1.pyANALYSIS
    """Lab 9 analysis of musrSim's t1 tree: event-level vs hit-level, then a lifetime fit.

    pip install uproot awkward numpy scipy
    python3 analyse_t1.py data/musrSim_201.root

Works on real musrSim output and on the synthetic file from make_synthetic_t1.py.
"""
import sys

import awkward as ak
import numpy as np
import uproot
from scipy.optimize import curve_fit

path = sys.argv[1] if len(sys.argv) > 1 else "data/musrSim_201.root"
with uproot.open(path) as f:
    t = f["t1"]
    d = t.arrays(["det_n", "det_ID", "det_edep", "det_time_start",
                  "muDecayTime", "muDecayDetID"], library="ak")
    print("events:", t.num_entries)

# --- event-level vs hit-level -----------------------------------------------
print("hits per event (mean det_n):", round(float(ak.mean(d.det_n)), 3))
all_edep = ak.flatten(d.det_edep)                      # every hit in every detector
mask = d.det_ID == 11                                  # jagged mask, same shape as det_edep
edep_F1 = ak.flatten(d.det_edep[mask])                 # mask FIRST, then flatten
print("hits in all detectors:", len(all_edep), "  hits in det 11:", len(edep_F1),
      "  mean Edep det 11 [MeV]:", round(float(np.mean(edep_F1)), 3))
try:
    wrong = ak.flatten(d.det_edep)[mask]               # flatten FIRST: the event structure is gone
    print("flatten-then-mask returned", len(wrong), "values (not what you wanted)")
except Exception as err:
    print("flatten-then-mask fails:", type(err).__name__)

# --- lifetime of muons that decayed in volume 201 ----------------------------
def decay(tt, N0, tau, bkg):
    return N0 * np.exp(-tt / tau) + bkg

tdec = np.asarray(d.muDecayTime)
sel = np.asarray(d.muDecayDetID) == 201
print("sentinel values (-1000) in muDecayTime:", int((tdec == -1000).sum()))

# A sentinel is not a measurement. A fixed histogram range happens to hide it; a mean does not.
print("mean decay time, sentinels kept   [us]:", round(float(tdec[sel | (tdec == -1000)].mean()), 2))
good = sel & (tdec > 0)
print("mean decay time, sentinels removed [us]:", round(float(tdec[good].mean()), 4))

tt = tdec[good]
counts, edges = np.histogram(tt, bins=120, range=(0, 12))
centres = 0.5 * (edges[:-1] + edges[1:])
# Counts are Poisson: weight each bin by the variance the model predicts (Pearson chi2),
# iterate once so the weights come from the fit, not from the noisy counts, and keep the
# absolute errors. An unweighted fit lets the many near-empty tail bins pull as hard as
# the full bins near t = 0, and its quoted error is not an uncertainty.
popt, _ = curve_fit(decay, centres, counts, p0=[counts.max(), 2.2, 0.0])
for _ in range(2):
    sigma = np.sqrt(np.maximum(decay(centres, *popt), 1.0))
    popt, pcov = curve_fit(decay, centres, counts, p0=popt, sigma=sigma, absolute_sigma=True)
chi2 = float((((counts - decay(centres, *popt)) / sigma) ** 2).sum())
print(f"fit: tau = {popt[1]:.4f} +/- {np.sqrt(pcov[1, 1]):.4f} us   (PDG mu+: 2.1970 us)"
      f"   chi2/ndf = {chi2:.1f}/{len(counts) - 3}")

    #!/bin/bash
# Lab 9: split one macro into independent jobs, with seeds that actually differ.
# The seed offset (3rd argument) only takes effect with /musr/run/randomOption 1
# (seed = computer time + 100 x offset). The course's 201.mac already sets it; the
# check below adds it to any other macro you point the script at.
set -euo pipefail
MAC=${1:-201.mac}                 # the run number is atoi() of this file name
NJOBS=${2:-50}
cd "$(dirname "$0")"              # run where the macro lives
mkdir -p data                     # musrSim writes data/musrSim_<run>_<name>.root and will not create data/
PROD=${MAC%.mac}_prod.mac
sed 's|^/musr/run/randomOption .*|/musr/run/randomOption 1|' "$MAC" > "$PROD"
if ! grep -q '^/musr/run/randomOption 1' "$PROD"; then
  { echo '/musr/run/randomOption 1'; cat "$PROD"; } > "$PROD.tmp"
  mv "$PROD.tmp" "$PROD"
fi
RUN=$(basename "$MAC" | sed 's/[^0-9].*//'); RUN=${RUN:-0}   # atoi(), as musrSim does
for i in $(seq 1 "$NJOBS"); do
  ../musrSim "$PROD" job${i} ${i} > data/job${i}.log 2>&1
  grep -m1 "seed1:" data/job${i}.log || true   # keep the seeds: they are your provenance
done
hadd -f data/musrSim_${RUN}_merged.root data/musrSim_${RUN}_job*.root
