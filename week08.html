Data are tables: one row per event, one column per measured quantity.数据就是表格：一行一个事例，一列一个测量量。

Background · ROOT files and ntuplesROOT 文件与 ntuple

An ntuple is a table, like a spreadsheet or a CSV file, where each row is an event and each column a quantity: time, energy deposited, which channel fired. ROOT is the particle-physics file format and toolkit for such tables. With the Python package uproot you can read it into NumPy without installing ROOT.

ntuple 就是一张表，像电子表格或 CSV 文件：每一行是一个事例，每一列是一个量，比如时间、沉积能量、哪个通道响应。ROOT 是粒子物理处理这类表格的文件格式和工具包。用 Python 包 uproot 可以直接读入 NumPy，无需安装 ROOT。

Background · Truth versus measurement真值与测量值

A simulation knows everything: the muon's true energy and path. A real detector only knows hit times, positions and pulse heights. Keep the two in separate tables, and make the measured one look exactly like the real data acquisition (DAQ) output. Then the same analysis program runs on both.

模拟知道一切：缪子的真实能量和路径。真实探测器只知道击中时间、位置和脉冲幅度。把两者放在不同的表里，并让测量表与真实数据采集（DAQ）的输出完全一致。这样同一个分析程序可以在两者上运行。

For muography projects用于缪子成像工程

A muography result is usually a ratio: the measured count along each direction divided by the simulated count for a reference model (or by an open-sky measurement). That only works if field data and simulation pass through the same reconstruction code, which is this week's DAQ-parity rule.

缪子成像的结果通常是一个比值：每个方向上的实测计数除以参考模型的模拟计数（或除以开阔天空的测量）。只有当野外数据和模拟经过同一套重建代码时，这才行得通，也就是本周的 DAQ 一致性原则。

New to muons, units such as g/cm² or m.w.e., or muography? Start with the background primer.还不熟悉缪子、g/cm² 或米水当量这类单位，或缪子成像？先读入门背景。

/control/manual9.1 · DAQ parity9.1 · DAQ 一致性

Make the simulated event look like a real DAQ event.让模拟事例看起来像真实的 DAQ 事例。

Keep the simulated output as close as possible to the laboratory DAQ format. The point is not to imitate every byte of a commercial digitizer. The point is that the same decoder and the same analysis can consume simulated and real data, so the simulation becomes a test bench for the analysis software rather than a separate universe. A deliberately simple raw packet carries run, event, timestamp, trigger word, number of channels, and per-channel records.

让模拟输出尽可能接近实验室 DAQ 格式。目的不是模仿商用数字化器的每一个字节，而是让同一个解码器和同一个分析程序既能处理模拟数据、也能处理真实数据。这样模拟就成了分析软件的测试平台，而不是另一个平行宇宙。一个刻意简化的原始数据包包含：运行号、事例号、时间戳、触发字、通道数，以及每个通道的记录。

Geant4 → events → detector response → DAQ-like record → ROOT → analysis

Definition 9.1 · The full simulation-to-data chain完整的模拟—数据链

Geant4 generates events; detector response generates hits; DAQ-style formatting packs each event's key quantities into one record; the record is written to a ROOT tree; downstream analysis reads it. Every link should explain itself, with clear variable names and explicit units, so the analysis never needs the Geant4 source.

Geant4 产生事例，探测器响应产生击中，DAQ 式格式化把每个事例的关键量打包成一条记录，记录写入 ROOT 树，下游分析读取它。每一环都应自我说明——变量名清楚、单位明确——这样分析时永远不需要 Geant4 源码。

Write two decoders, one for the lab binary packet and one for the simulated record. Feed both into the same writer, then run the same selection on both. A branch with no hardware analogue, such as Edep, goes in a separate truth tree, never in the detector-facing one.

/run/numberOfThreads 29.2 · someone else's data9.2 · 给别人用的数据

A simulation's real endpoint is someone else being able to use your data.模拟的真正终点，是别人能够使用你的数据。

In a research group one person produces simulated data and another analyses it, sometimes the same person months later. A structured file is the only interface. This week also returns to the textbook's G4RunManagerType::Default, which makes the run multithreaded. Two things change. Every worker thread has its own RunAction and its own analysis objects: histograms are merged automatically, but ntuples need SetNtupleMerging(true). And plain counters in RunAction only count that worker's events, so the course switches them to G4Accumulable, which the master sums.

在研究组里，一个人生产模拟数据，另一个人分析——有时是同一个人在几个月后。结构化文件是唯一的接口。本周也回到教材的 G4RunManagerType::Default，运行变为多线程。这带来两点变化：每个工作线程都有自己的 RunAction 和分析对象，直方图会自动合并，ntuple 则需要 SetNtupleMerging(true)；RunAction 里的普通计数器只统计本线程的事例，所以本课程改用 G4Accumulable，由主线程汇总。

Intuition · a translation pipeline直觉 · 翻译流水线

Geant4 speaks C++ objects, the ROOT tree speaks tables, the analysis speaks arrays and histograms. Every translation can introduce errors or lose information, so keep each one transparent and checkable.

Geant4 说的是 C++ 对象，ROOT 树说的是表格，分析脚本说的是数组和直方图。每一次翻译都可能引入错误或丢失信息，所以要让每一步都透明、可检查。

Think about it想一想

An analysis script finds a variable that is entirely zero or entirely constant. Which link is most likely at fault: Geant4's physics, hit generation, or the tree-writing code? With the fewest steps, how would you find out? Hint: print the value in EndOfEventAction for three events.

分析脚本发现某个变量全为零或全为常数。最可能出问题的是哪一环：Geant4 物理、击中产生，还是写树的代码？用最少的步骤怎样确定？提示：在 EndOfEventAction 中打印三个事例的值。

    include/RunAction.hhGEANT4
    #ifndef RunAction_h
#define RunAction_h 1

#include "G4Accumulable.hh"
#include "G4UserRunAction.hh"
#include "globals.hh"

class G4Run;

// In a multithreaded run every worker has its own RunAction. Plain member counters
// would only see that worker's events; G4Accumulable values are summed into the
// master's copy by G4AccumulableManager::Merge().
class RunAction : public G4UserRunAction
{
  public:
    RunAction();
    void BeginOfRunAction(const G4Run*) override;
    void EndOfRunAction(const G4Run* run) override;

    void Count(G4bool fired0, G4bool fired1, G4bool trigger)
    {
      fN0 += fired0 ? 1 : 0;
      fN1 += fired1 ? 1 : 0;
      fTrig += trigger ? 1 : 0;
    }

  private:
    G4Accumulable<G4int> fN0{0};
    G4Accumulable<G4int> fN1{0};
    G4Accumulable<G4int> fTrig{0};
};

#endif
    
            
    src/RunAction.ccGEANT4
    #include "RunAction.hh"

#include "G4AccumulableManager.hh"
#include "G4AnalysisManager.hh"
#include "G4Run.hh"
#include "G4ios.hh"

#include <cmath>

RunAction::RunAction()
{
  G4AccumulableManager::Instance()->Register(fN0);
  G4AccumulableManager::Instance()->Register(fN1);
  G4AccumulableManager::Instance()->Register(fTrig);

  auto* analysis = G4AnalysisManager::Instance();
  analysis->SetDefaultFileType("root");
  analysis->SetFileName("muons");
  // In a multithreaded run, merge ROOT ntuples into one output file.
  // Histograms are merged automatically; ntuples require this explicit opt-in.
  analysis->SetNtupleMerging(true);

  // Ntuple 0: what the DAQ would write. Detector-facing names, units in the names,
  // and only TRIGGERED events, exactly like the hardware stream.
  analysis->CreateNtuple("daq", "DAQ-like event record (triggered events only)");
  analysis->CreateNtupleIColumn("run");
  analysis->CreateNtupleIColumn("event");
  analysis->CreateNtupleDColumn("timestamp_ns");   // synthetic 1 kHz clock: event x 1e6 ns
  analysis->CreateNtupleIColumn("trigger_word");   // bit0 ch0 > thr, bit1 ch1 > thr, bit2 coincidence
  analysis->CreateNtupleIColumn("n_channels");
  analysis->CreateNtupleDColumn("ch0_adc");        // ADC counts
  analysis->CreateNtupleDColumn("ch1_adc");
  analysis->CreateNtupleDColumn("ch0_time_ns");
  analysis->CreateNtupleDColumn("ch1_time_ns");
  analysis->FinishNtuple();

  // Ntuple 1: simulation truth, kept OUT of the detector-facing record. Every event.
  analysis->CreateNtuple("truth", "Monte Carlo truth (all events)");
  analysis->CreateNtupleIColumn("event");
  analysis->CreateNtupleDColumn("E0_MeV");
  analysis->CreateNtupleDColumn("cos_theta");
  analysis->CreateNtupleDColumn("Edep0_MeV");
  analysis->CreateNtupleDColumn("Edep1_MeV");
  analysis->CreateNtupleIColumn("triggered");
  analysis->FinishNtuple();
}

void RunAction::BeginOfRunAction(const G4Run*)
{
  G4AccumulableManager::Instance()->Reset();
  G4AnalysisManager::Instance()->OpenFile();
}

void RunAction::EndOfRunAction(const G4Run* run)
{
  auto* accumulables = G4AccumulableManager::Instance();
  accumulables->Merge();   // on the master: sum of all workers

  if (IsMaster()) {
    const G4int n = run->GetNumberOfEvent();
    if (n > 0) {
      const G4double e = static_cast<G4double>(fTrig.GetValue()) / n;
      G4cout << "Run " << run->GetRunID() << " complete: " << n << " events (all threads)" << G4endl
             << "  top fired " << fN0.GetValue() << ", bottom fired " << fN1.GetValue()
             << ", triggered " << fTrig.GetValue() << G4endl
             << "  trigger efficiency = " << e << " +/- " << std::sqrt(e * (1 - e) / n) << G4endl;
    }
  }
  auto* analysis = G4AnalysisManager::Instance();
  analysis->Write();
  analysis->CloseFile();
}

    src/EventAction.ccGEANT4
    #include "EventAction.hh"

#include "MuonHit.hh"
#include "RunAction.hh"

#include "G4AnalysisManager.hh"
#include "G4Event.hh"
#include "G4HCofThisEvent.hh"
#include "G4PrimaryParticle.hh"
#include "G4PrimaryVertex.hh"
#include "G4Run.hh"
#include "G4RunManager.hh"
#include "G4SDManager.hh"
#include "G4SystemOfUnits.hh"

#include <cmath>

void EventAction::EndOfEventAction(const G4Event* event)
{
  if (fHitsCollectionID < 0)
    fHitsCollectionID = G4SDManager::GetSDMpointer()->GetCollectionID("MuonHitsCollection");
  auto* hce = event->GetHCofThisEvent();
  if (!hce) return;
  auto* hits = static_cast<MuonHitsCollection*>(hce->GetHC(fHitsCollectionID));
  if (!hits || hits->entries() < 2) return;

  // truth
  const G4double edep[2] = {(*hits)[0]->GetEdep(), (*hits)[1]->GetEdep()};
  const G4PrimaryParticle* primary = event->GetPrimaryVertex()->GetPrimary();
  const G4double e0 = primary->GetKineticEnergy();
  const G4double cosTheta = primary->GetMomentumDirection().z();

  // detector response -> digitization -> trigger (Week 5 chain)
  Signal sig[2];
  for (G4int i = 0; i < 2; ++i) sig[i] = fDigitizer.Digitize((*hits)[i]->GetEvis(), (*hits)[i]->GetTime());
  const G4bool above0 = sig[0].adc > fAdcThreshold, above1 = sig[1].adc > fAdcThreshold;
  const G4bool coinc = above0 && above1 && std::abs(sig[0].time - sig[1].time) < fCoincidenceWindow;
  const G4int triggerWord = (above0 ? 1 : 0) | (above1 ? 2 : 0) | (coinc ? 4 : 0);

  fRunAction->Count(edep[0] >= fEdepThreshold * MeV, edep[1] >= fEdepThreshold * MeV, coinc);

  auto* analysis = G4AnalysisManager::Instance();
  const G4int evt = event->GetEventID();
  if (coinc) {   // the DAQ only writes what the trigger accepts
    const G4int run = G4RunManager::GetRunManager()->GetCurrentRun()->GetRunID();
    analysis->FillNtupleIColumn(0, 0, run);
    analysis->FillNtupleIColumn(0, 1, evt);
    analysis->FillNtupleDColumn(0, 2, evt * 1.0e6);
    analysis->FillNtupleIColumn(0, 3, triggerWord);
    analysis->FillNtupleIColumn(0, 4, 2);
    analysis->FillNtupleDColumn(0, 5, sig[0].adc);
    analysis->FillNtupleDColumn(0, 6, sig[1].adc);
    analysis->FillNtupleDColumn(0, 7, sig[0].time);
    analysis->FillNtupleDColumn(0, 8, sig[1].time);
    analysis->AddNtupleRow(0);
  }
  analysis->FillNtupleIColumn(1, 0, evt);
  analysis->FillNtupleDColumn(1, 1, e0 / MeV);
  analysis->FillNtupleDColumn(1, 2, cosTheta);
  analysis->FillNtupleDColumn(1, 3, edep[0] / MeV);
  analysis->FillNtupleDColumn(1, 4, edep[1] / MeV);
  analysis->FillNtupleIColumn(1, 5, coinc ? 1 : 0);
  analysis->AddNtupleRow(1);
}

    parity.pyANALYSIS
    """Mission 8B: one analysis for simulation and hardware.

A deliberately simple 'laboratory' binary format (one header + two channel records per
event, little-endian) stands in for a real digitizer. The simulated ROOT 'daq' tree is
written into that format, decoded again, and both streams go through the SAME analysis
function, which never asks where the events came from.

    python3 parity.py
"""
import struct

import numpy as np
import uproot

HEADER = struct.Struct("<IQQIH")   # run, event, timestamp_ns, trigger_word, n_channels
CHANNEL = struct.Struct("<Hff")    # channel id, adc, time_ns


def canonical_from_root(path):
    """Decoder 1: the simulation's ROOT tree -> canonical arrays."""
    with uproot.open(path) as f:
        d = f["daq"].arrays(library="np")
    return {"run": d["run"], "event": d["event"], "timestamp_ns": d["timestamp_ns"].astype(np.uint64),
            "trigger_word": d["trigger_word"], "adc": np.stack([d["ch0_adc"], d["ch1_adc"]], axis=1),
            "time_ns": np.stack([d["ch0_time_ns"], d["ch1_time_ns"]], axis=1)}


def write_binary(ev, path):
    """Pack canonical events into the lab-style binary stream (what the digitizer would write)."""
    with open(path, "wb") as out:
        for i in range(len(ev["event"])):
            out.write(HEADER.pack(int(ev["run"][i]), int(ev["event"][i]), int(ev["timestamp_ns"][i]),
                                  int(ev["trigger_word"][i]), 2))
            for ch in range(2):
                out.write(CHANNEL.pack(ch, float(ev["adc"][i, ch]), float(ev["time_ns"][i, ch])))


def canonical_from_binary(path):
    """Decoder 2: the lab binary stream -> the same canonical arrays."""
    rows = {k: [] for k in ("run", "event", "timestamp_ns", "trigger_word", "adc", "time_ns")}
    with open(path, "rb") as f:
        while (head := f.read(HEADER.size)):
            run, evt, ts, tw, nch = HEADER.unpack(head)
            adc, tim = [0.0, 0.0], [0.0, 0.0]
            for _ in range(nch):
                ch, a, t = CHANNEL.unpack(f.read(CHANNEL.size))
                adc[ch], tim[ch] = a, t
            for k, v in (("run", run), ("event", evt), ("timestamp_ns", ts), ("trigger_word", tw), ("adc", adc), ("time_ns", tim)):
                rows[k].append(v)
    return {k: np.array(v) for k, v in rows.items()}


def analysis(ev):
    """The ONE analysis. Selects with the trigger word only."""
    sel = (ev["trigger_word"] & 4) != 0
    adc = ev["adc"][sel]
    dt = ev["time_ns"][sel, 0] - ev["time_ns"][sel, 1]
    return {"n": int(sel.sum()), "mean_adc_top": round(float(adc[:, 0].mean()), 3),
            "mean_adc_bottom": round(float(adc[:, 1].mean()), 3), "rms_dt_ns": round(float(dt.std()), 3)}


sim = canonical_from_root("muons.root")
write_binary(sim, "lab_stream.bin")
lab = canonical_from_binary("lab_stream.bin")
a, b = analysis(sim), analysis(lab)
print("from ROOT  :", a)
print("from binary:", b)
print("identical  :", a == b)
